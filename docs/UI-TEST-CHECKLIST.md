# UI・インストーラーの試験チェックリスト(全リポジトリ共通)

pdf-r2l-rs の v1.0.2〜v1.0.3 の開発で、実際に不具合を見つけて直した確認項目をまとめたものです。
**GUI・Android アプリ・インストーラーを作る/変更するときは、リリース前に必ずこの表を通します。**
(common checklist for every GUI / Android app / installer in the aon-co-jp projects)

## 1. 画面(PC・スマホ・タブレット、縦・横)

| # | 確認項目 | 見つけた不具合の例 | 直し方 |
|---|---|---|---|
| 1 | 小さいスマホ(720×1280)・標準スマホ・10インチタブレット、縦と横で、**全ての操作が画面内で届く** | 横向きで下部のボタンが画面外/スクロールの奥 | 主要ボタン・進捗・結果は**画面下に固定**(スクロールさせない) |
| 2 | **文字が読める**(暗い背景に暗い灰色になっていないか) | 見出し・補足が灰色で読みにくい | 文字色はテーマの標準色(`textColorPrimary` など)を明示 |
| 3 | 広い画面(タブレット・横向き)で、**ボタン・入力欄が横いっぱいに伸びない** | タブレット横でボタンが画面幅 | 内容の幅を最大 640dp 程度にして中央寄せ |
| 4 | 横向き・ノッチ・ジェスチャーバーで**端が隠れない** | 横向きで左右が切れる、下バーに重なる | システムの余白(insets)を上下左右すべて反映 |
| 5 | 文字サイズを大きくした設定(フォントスケール 1.5)でも崩れない | — | 固定の高さ・幅を使わず、折り返し・スクロールで吸収 |
| 6 | 回転・画面サイズ変更で、**入力中の値・進行中の処理が失われない** | — | `configChanges` で再作成を避ける/状態を保存 |
| 7 | 空のメッセージ欄が場所を取らない | 下部バーが縦に長くなり、横向きで本体が見えない | 空なら非表示(GONE) |
| 8 | ボタンは**1行にまとめられるものはまとめる**(狭い画面の縦幅を節約) | 変換とライセンスが縦に2つ | 横並び(重み付け) |

撮影: `scripts/ui-test/android-matrix.sh <パッケージ> <アクティビティ>`(解像度×向き×文字サイズを一括撮影)。
PC: `scripts/ui-test/shot.ps1`(ウィンドウを DPI 対応で撮影)。画面の自動操作が難しいときは、画面を使わずに処理を呼べる**デバッグ専用フック**(デバッグビルドだけ有効)を用意する。

## 2. 機能の通し試験(実機・実データ)

- 実際のサーバー・実際のファイルで、**入力 → 処理 → 出力 → 出力を別の道具で読み直す**(例: poppler の `pdftotext` / `pdftoppm`)。ビルドが通っただけで完了にしない。
- 失敗の経路も試す: 通信できない/ファイルが壊れている/途中でキャンセル。**失敗しても元のファイルを壊さない**(一時ファイル→置き換え)、エラーは**日英で原因と次の行動**を示す(例: 「OCRなしで変換」ボタン)。
- 時間のかかる処理は**進捗とキャンセル**を出す。重い処理は**まとめ処理・並行処理・不要な処理の省略**(白紙ページなど)を検討し、前後で実測して比べる。
- 判定ロジック(書体・太字など)は、**答えの分かっている見本**を作って正解率を測り、基準値を決める(推測で決めない)。

## 3. インストーラー(Windows / macOS / Linux / Android)

- Windows: `scripts/ui-test/install-uninstall-test.ps1`。**アプリを起動したままアンインストール**して、ファイルが全て消えるか(使用中のロックで「削除できませんでした」にならないか)。→ アンインストール前にプロセスを終了(`taskkill`)、`[UninstallDelete]` で残りを掃除、画面ありの場合は設定・キャッシュも消すか尋ねる。
- 上書きインストール(更新)で、起動中のアプリを閉じてから置き換える(`CloseApplications`)。
- 無人インストールで、アプリが勝手に起動して**ファイルを掴んだままにならない**(`skipifsilent`)。
- Android: 署名鍵が既存版と違うと更新できない(`INSTALL_FAILED_UPDATE_INCOMPATIBLE`)。鍵は変えず、安全な場所に控える。
- ライセンスは**インストーラーの途中とアプリ内**の両方で、英語・日本語で見られること。

## 4. 変更を出す前に

- 単体テスト・`clippy -D warnings`・フォーマットを通す。
- CI で全 OS のビルドが成功することを確認してからタグを打つ(`workflow_dispatch` で先に試す)。
- 確認できていないこと(実機の無い OS など)は、リリースノート・README に**正直に書く**。
